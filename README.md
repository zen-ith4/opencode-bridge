# OpenCode Bridge

A VS Code / VSCodium chat client for [OpenCode](https://opencode.ai) (opencode.ai).

The extension does **not** call any LLM API itself. It connects to a local
OpenCode HTTP server (`opencode serve`), which already holds the model and API
key configuration. Model inference stays inside that server.

## Features

### Server lifecycle (two modes)

- **Managed mode** (default, `opencodeBridge.serverMode = "managed"`): the
  extension starts its **own private** `opencode serve` child on a free
  auto-chosen port with a random password. The password is generated by the
  extension and passed only via `OPENCODE_SERVER_PASSWORD` in the child
  environment. It is never logged and never written to settings.
  If the child dies unexpectedly it is restarted with exponential backoff
  (up to 3 attempts); after that the chat shows a visible error.
- **External mode** (`opencodeBridge.serverMode = "external"`): connect to an
  existing server at `opencodeBridge.hostname:opencodeBridge.port`. Password
  lookup order: VS Code secret store → `OPENCODE_SERVER_PASSWORD` → prompt.
  A 401/403 triggers one password prompt, then a visible "Enter password"
  banner if authentication still fails.

### Chat

- One compact header: brand, a searchable model picker grouped by provider,
  and icon buttons for refresh, new chat, stop and (external mode) password.
  Server mode, URL and workspace are available in the header tooltip only.
- Welcome card with the connected model and three suggestion chips that send a
  prompt immediately.
- User messages are right-aligned in a subtle bubble; assistant replies use
  the full width. Timestamps appear on hover.
- Live streaming through the server's `/api/event` SSE stream with a typing
  indicator, exactly one subscription, reconnect with backoff, and duplicate
  event-id protection. Each event sends **only the new chunk** to the webview;
  the full accumulated answer is never re-sent per delta, so postMessage
  traffic stays linear instead of quadratic.
- Markdown: headings, lists, blockquotes, bold/italic, inline code, simple
  tables, and links limited to `http:`, `https:` and `mailto:`. Raw HTML is
  escaped, and `javascript:`, `data:`, `vbscript:` and protocol-relative
  (`//host`) links are rendered as text. Code blocks have a language label,
  Copy (copies the original raw code) and a Wrap toggle. Code blocks and tool
  input/output (`<pre>`) are forced `dir="ltr"` with left alignment so mixed
  Persian/English code does not reorder; prose stays `dir="auto"`.
- Composer auto-grows up to about 8 lines. `Enter` sends,
  `Shift+Enter` inserts a newline. Send turns into Stop while generating.
- Smart auto-scroll: if you scroll up, streaming stops following and a
  "Jump to latest" button appears.
- `dir="auto"` message bodies and composer for correct Persian/Arabic text,
  with a Persian-friendly font stack.
- Session history is restored from
  `GET /api/session/{id}/message?order=asc` when the view reloads.
  `retainContextWhenHidden` keeps the DOM/scroll state while the view is hidden.
- One dismissible banner with a Details expander and contextual actions
  (Retry, Enter password, Open logs, Cancel). Inline bubbles are only used for
  failed prompts.

### Long streams and runaway output

Long answers used to re-parse the whole Markdown document on every delta,
which is O(n²) and freezes the webview on stories of a few hundred thousand
characters. The renderer is now incremental and coalesced:

- Deltas are accumulated in the webview. Completed top-level Markdown blocks
  (a blank line outside a fenced code block) are rendered **once** and
  appended; only the still-open tail is re-rendered.
- Renders are coalesced to at most one per `requestAnimationFrame`, and the
  final `assistant-end` does one full pass so the finished answer is complete.
- Scroll stickiness is preserved: rendering never yanks the view if you have
  scrolled up.
- Above **~200,000 characters** live Markdown stops. The message switches to a
  plain-text tail with a “Show full output” toggle (and back to “Show tail
  only”), so the panel stays responsive. The full text remains available.
- A **repetition guard** watches only the trailing ~400 characters. More than
  200 copies of one character, or a short pattern repeated at least 8 times
  over ≥160 characters, raises a banner with **Stop**, **Stop and retry with a
  different model**, and **Dismiss**. The message is kept and the banner names
  the model. Set `opencodeBridge.autoStopRepetition` to `true` to interrupt
  automatically instead of asking.
- `session.execution.failed`, `session.step.failed` and provider-level tool
  failures are classified (connection, authentication, rate limit, model,
  extension). The banner names the model/provider, says plainly whether this
  is an extension error, and offers **Retry**, **Switch model**, **Open logs**
  and, when the provider rejected the request, **Enter password**. Partial
  text is kept, marked **incomplete**, and gets a **Continue** button that
  sends a follow-up asking the model to resume at the cut-off point.

### Thinking, tools, permissions and questions

- **Reasoning / thinking blocks.** `session.reasoning.*` streams into a
  collapsible block above the answer with a live elapsed timer. It collapses
  automatically when the answer text starts, and is restored from history
  (`content[].type === "reasoning"`).
- **Tool cards.** `session.tool.*` renders one card per call with a kind icon
  (read / edit / write / bash / search / web / subagent / todo), a title
  derived from the input (`path`, `command`, `pattern`, …), a
  pending/running/done/failed badge and a collapsible body. The body shows the
  input, output content and error. File paths open in the editor; the Diff
  button opens the session's unified patch. A **Files changed** summary is
  appended at the end of the turn, merging `step.ended.files` with paths from
  write/edit inputs.
- **Permissions.** `permission.asked` shows an Allow once / Allow always /
  Reject card. Replies use the verified enum `"once" | "always" | "reject"`.
  Pending requests are fetched again on reconnect
  (`GET /api/session/{id}/permission`). With
  `opencodeBridge.permissions = "readOnlyAuto"` only read-only actions
  (`read`, `grep`, `glob`, `list`, `search`, `find`, `webfetch`, `websearch`)
  are auto-answered with `"once"`; edits, writes and shell commands always
  ask, and `"always"` is never chosen automatically.
- **Questions.** In v2.3.0 a question is a form (`form.created`,
  `GET /api/session/{id}/form`). The webview renders its fields (string with
  options, multiselect, boolean, number/integer, custom "Other…") and replies
  with `{ answer }` to `POST /form/{formID}/reply`.
- **Agents.** A header dropdown lists primary, non-hidden agents from
  `GET /api/agent`. The choice is applied with
  `POST /api/session/{id}/agent`, passed when creating a session, and kept in
  sync with `session.agent.selected`. `Shift+Tab` and `Ctrl+.` cycle agents.
- **Slash palette.** Typing `/` opens a keyboard-filterable palette. Built-ins
  are `/new`, `/sessions`, `/models`, `/compact`, `/undo`, `/redo`, `/agent`
  and `/clear`. Custom commands from `GET /api/command` run through
  `POST /api/session/{id}/command {name,text}` (verified: the template is
  expanded into a user message). Skills from `GET /api/skill` are not
  first-class commands in v2.3.0, so selecting one inserts a prompt that names
  the skill.
- **Sessions.** A searchable picker lists `GET /api/session` newest first with
  cursor pagination, title, relative time and directory, and marks running
  sessions. Switching loads the full history, agent and model. **New chat**
  returns to an empty view, and the last session is stored per workspace in
  `workspaceState`.
- **Context meter.** Shows `used / limit` and a percentage from the selected
  model's `limit.context`, using the latest `step.ended.tokens` as
  `input + cache.read` (the server's cumulative `session.tokens` is not used).
  The bar turns yellow above 70% and red above 90%; the tooltip shows the
  token breakdown and cost. **Compact** calls
  `POST /api/session/{id}/compact` and shows compaction progress from
  `session.compaction.*`.
- **Model variants.** When a model exposes `variants[]`, a selector applies
  the chosen reasoning effort through the verified
  `Model.Ref = { id, providerID, variant? }` field.

### Diagnostics

- Every error is written to the **OpenCode Bridge** Output channel
  (without secrets). Debug logs are added when `opencodeBridge.debug` is on.
- `OpenCode: Show Logs` opens the channel.

### Editor integration

- `OpenCode: Ask about selection` sends the selected code, file path and line
  range as context (also in the editor context menu).
- `OpenCode: Add current file as context` sends the whole current file.
- `Ctrl+Alt+O` (`Cmd+Alt+O` on macOS) opens the chat.

## Requirements

- [OpenCode CLI](https://opencode.ai/docs) installed (`opencode` on PATH, or
  set `opencodeBridge.opencodePath`).
- A model provider configured in OpenCode (API keys set in OpenCode), since the
  extension does not provide any model itself.
- VS Code / VSCodium 1.85+.

## Setup

### From a `.vsix`

1. Install `opencode-bridge-0.1.0.vsix` via
   **Extensions** → `...` → **Install from VSIX…**.
2. Managed mode needs no setup. For external mode, set
   `opencodeBridge.serverMode` to `"external"` and start a server:
   ```sh
   opencode serve --port 4096
   ```
3. Open the **OpenCode Bridge** activity-bar view and start chatting.

### From source (F5)

```sh
npm install
npm run typecheck    # tsc --noEmit (includes the esbuild entry)
npm run lint
npm test             # markdown / slash / events / controller / streaming / managed-server tests
```

Press **F5**. The preLaunch task `OpenCode Bridge: bundle` runs
`npm run package` (esbuild), which is the same build used by the `.vsix`.

### Build a `.vsix`

```sh
npm run package:vsix
```

This runs the esbuild bundle and then `@vscode/vsce package`. The bundle is
written to `out/extension.cjs`; `.vscodeignore` excludes `src`, tests,
`node_modules` and editor files from the package.

### Live integration check

With `opencode` installed and a provider configured:

```sh
npm run test:integration
```

The script starts a real managed server with a random password and checks:

- the generated password is enforced,
- `GET /api/provider` and `GET /api/model` match `opencode models`,
- `GET /api/agent`, `/command`, `/skill`, `/session`, `/session/active`,
  `/session/{id}`, `/session/{id}/permission`, `/form` and `/diff` respond
  with the expected shapes,
- the ready handshake opens exactly one SSE subscription,
- a prompt is accepted and SSE events are parsed,
- event ids are applied at most once and streamed text is not duplicated,
- `assistant-delta` messages carry only `delta` (never the full accumulated
  text), and the concatenated deltas match the server's text events.

A full run against a local `opencode v2.3.0` with a configured provider exits
`0` and covers the managed-server restart and auth enforcement as well.

If no model provider is reachable, the script still reports the structural
result and says that no reply was received.

## Configuration

```json
{
  "opencodeBridge.serverMode": "managed",
  "opencodeBridge.port": 4096,
  "opencodeBridge.hostname": "127.0.0.1",
  "opencodeBridge.autoStartServer": true,
  "opencodeBridge.opencodePath": "opencode",
  "opencodeBridge.model": "",
  "opencodeBridge.responseTimeoutSeconds": 120,
  "opencodeBridge.debug": false,
  "opencodeBridge.permissions": "ask",
  "opencodeBridge.autoStopRepetition": false
}
```

| Setting | Default | Meaning |
|---|---|---|
| `serverMode` | `"managed"` | Start a private server or connect to an existing one. |
| `port` / `hostname` | `4096` / `"127.0.0.1"` | External-mode endpoint. |
| `autoStartServer` | `true` | Legacy setting, kept for compatibility. Managed mode always starts its own server; external mode only connects. |
| `opencodePath` | `"opencode"` | CLI path/name. |
| `model` | `""` | Optional `providerID/modelID`; empty uses the server default. |
| `responseTimeoutSeconds` | `120` | Quiet time before a non-blocking "Still waiting" status with Cancel. Reset by any event for the current session. |
| `debug` | `false` | Verbose lines in the Output channel. |
| `permissions` | `"ask"` | `"ask"` shows a card for every permission request. `"readOnlyAuto"` auto-replies `"once"` to read-only requests only. |
| `autoStopRepetition` | `false` | Stop generation automatically when a degenerate repetition loop is detected. When `false`, a banner offers Stop / switch model / Dismiss. |
| `ui.textDirection` | `auto` | `auto`, `ltr` or `rtl`. With `auto`, each paragraph picks its own direction, so Persian/Arabic text is right-aligned and English stays left-aligned. |
| `ui.fontFamily` | `""` | Chat font (for example `Vazirmatn, Tahoma, sans-serif`). Empty uses the editor UI font. |
| `ui.fontSize` | `0` | Chat font size in px (8-32). `0` uses the editor font size. |
| `ui.modelLabelMaxWidth` | `160` | Widest the model name may get in the composer toolbar (60-400 px) before it is cut with an ellipsis. |
| `ui.showToolControls` | `true` | Show **Stop** and **Run in background** buttons on a running tool call such as a shell command. |

**Stopping and backgrounding a running command.** The **Stop** button on a running tool card interrupts the turn (and the command it is waiting on). If the server rejects the interrupt, a banner says so and offers **Try stopping again** instead of pretending it worked. **Run in background** asks OpenCode to detach blocking work; the server currently only detaches subagents, so for a plain shell command it reports that nothing could be moved and you should use Stop.

## Password handling

### Managed mode

No configuration needed. A random password
(`crypto.randomBytes(24).toString("hex")`) is generated, the child gets
`OPENCODE_SERVER_PASSWORD` in its environment only, and requests use Basic auth
with username `opencode`. The password stays in memory and is never logged.
`OPENCODE_PASSWORD` is explicitly removed from the child environment.

### External mode

Set the password through **OpenCode: Set Server Password**, the 🔑 button or
the `OPENCODE_SERVER_PASSWORD` environment variable. It is stored under the
secret key `opencodeBridge.serverPassword`.
**OpenCode: Clear Server Password** removes the stored secret.

## Verified against OpenCode v2.3.0

Every endpoint and event below was checked against a live `opencode serve`
v2.3.0 and its `/openapi.json` (fetched with Basic auth):

- SSE payloads are `data: {"id","created","type","data"}` with **no** `event:`
  line; text and reasoning chunks are in `data.delta`. v1.19.6
  `session.next.*` aliases are normalized, so newer servers keep working.
- The bridge forwards text deltas as deltas. `session.text.ended` is used only
  to correct a missed chunk (a `resync` replacement), and history restore is
  the only other place a full text snapshot is sent.
- Canonical events used: `session.reasoning.*`, `session.tool.*`,
  `session.step.*`, `permission.asked/replied`, `form.created/replied/cancelled`,
  `session.agent.selected`, `session.model.selected`, `session.status`,
  `session.idle`, `session.execution.*` and `session.compaction.*`.
- `Permission.Reply` is `["once","always","reject"]`; the body is
  `{decision, message?}`; pending requests come from
  `GET /api/session/{id}/permission`.
- Questions are forms, not a `/question` route. Pending forms come from
  `GET /api/session/{id}/form`, and the reply body is `{answer}`.
- `session.prompt` has no model field. Switching model is
  `POST /api/session/{id}/model {model:{id,providerID,variant?}}`; session
  creation accepts `agent` and `model`.
- Custom commands work via `POST /api/session/{id}/command {name,text}`
  (HTTP 204; the template becomes a user message). Skills are not commands.
- `session.tool.success` has no reliable `outputPaths`; write/edit paths come
  from `input.path`, and `step.ended.files` can add more.
- There is no snapshot file-content endpoint. **Diff** opens the verified
  `/session/{id}/diff` unified patch in an untitled `diff` editor; clicking a
  file opens the file itself.
- There is no redo endpoint. **Redo** re-sends the last undone prompt;
  **Undo** stages and commits a revert of the last user message.

## Manual test steps

The automated tests cover the event reducer, slash filtering, context math and
the live structural endpoints. These UI behaviours still need a human:

1. **Thinking.** Send a prompt to a reasoning model. A block appears above the
   answer, streams, shows an elapsed timer and collapses when text starts.
   Reload the view: the reasoning is restored and collapsed.
2. **Tools.** Ask the agent to read a file. The card shows the file title, a
   running badge and expanded content; click the path to open the file, then
   **Files changed** lists it at the end.
3. **Permission.** Ask the agent to edit a file with `permissions = "ask"`.
   The card offers Allow once / Allow always / Reject; each completes the
   tool and removes the card. Switch to `readOnlyAuto` and confirm a read is
   auto-approved while an edit still asks.
4. **Question.** Trigger a question form and submit text, a select, a
   multiselect and a boolean; the card disappears after Submit.
5. **Agents.** Open the header agent dropdown, switch agents, and press
   `Shift+Tab` / `Ctrl+.`. The selection survives a view reload.
6. **Sessions.** Use `/sessions` to search, switch to an older session and
   confirm its full history, then **New chat**. Reload VS Code: the last
   session is restored for that workspace.
7. **Slash palette.** Type `/` and filter with each built-in, a custom command
   and a skill. `Enter`/`Tab` chooses, arrows move, `Escape` closes.
8. **Context meter and variants.** Check `used / limit`, tooltip breakdown and
   the yellow/red thresholds; run **Compact** and watch progress. If the model
   has variants, switch one and confirm the next step reports that variant.
9. **Long Persian story (streaming hardening).** Switch to a fast model and
   send:
   `یک داستان فارسی بسیار طولانی درباره‌ی پادشاه، سه دخترش و سفری به ستاره‌ها بنویس؛ حداقل چند هزار کلمه، با تیترها، فهرست‌ها و جدول.`
   While it streams:
   - text appears smoothly, without the panel freezing or the answer
     flickering/re-parsing;
   - scrolling up stops auto-follow and shows **Jump to latest**; scrolling
     back to the bottom resumes follow;
   - Markdown headings, lists, tables and code blocks render correctly, and
     code/tool output stays left-to-right inside a right-to-left page;
   - links render as links only for `http(s):`/`mailto:`; paste a
     `javascript:` or `data:` link and confirm it stays plain text.
   Above ~200,000 characters the message switches to the plain-text tail with
   **Show full output**; toggle it and confirm the full text is still there
   after the stream ends.
10. **Runaway loop and provider failure.**
    - Repetition: use a model/seed that loops (or temporarily lower the
      detector threshold in a scratch build). A banner appears naming the
      model with **Stop** / **Stop and retry with a different model** /
      **Dismiss**; Dismiss keeps the text streaming. Set
      `autoStopRepetition: true` and confirm it stops by itself.
    - Failure: replay the recorded `ECONNRESET` sequence
      (`test/streaming.test.mjs`) or disconnect the provider mid-answer. The
      partial text stays, is marked **incomplete**, the banner says it is not
      an extension error and names the model/provider, and **Continue** sends
      a follow-up that resumes the answer.

## Error handling

- **Streaming failures are attributed honestly.** `session.execution.failed`,
  `session.step.failed` and provider-level `session.tool.failed` messages are
  classified by `src/errors.ts`:
  - **connection** (`ECONNRESET`, `fetch failed`, socket closed, timeout):
    “OpenCode lost its connection to the model provider; this is not an
    extension error.” Retryable.
  - **authentication** (401/403, invalid key, OAuth): not retried; offers
    **Enter password**.
  - **rate limit** (429, quota, overloaded): retryable after a pause.
  - **model** (unknown model, context length, provider 4xx/5xx): retryable,
    usually worth switching models.
  - **extension** (`TypeError`, `is not a function`, …): an actual bridge bug.
  The banner always names the model (`provider/model`) and provider, keeps the
  partial answer, marks it **incomplete**, and offers **Retry**, **Switch
  model**, **Open logs** and **Continue**. The raw provider text stays in
  Details and the Output channel.
- **Repetition loops** are detected from the stream tail only (see above).
  The default is to warn, not to stop silently.
- **401/403** are never retried silently. External mode prompts once, stores
  the password in the secret store, and otherwise shows an "Enter password"
  banner.
- Network errors and 502/503 are retried with exponential backoff (about 10s).
- "No model providers" is shown **only** when `GET /api/provider` succeeds and
  returns zero providers. Other failures show the real HTTP status and a short
  response snippet.
- A slow model never produces a hard error: after
  `responseTimeoutSeconds` without events the chat says "Still waiting" and
  offers Cancel. Any event for the current session resets that timer.
- Events from other sessions (for example a session created by the TUI) are
  ignored. The extension only trusts the session id returned by its own
  `createSession` call.
- Errors are written to the **OpenCode Bridge** Output channel.

## Troubleshooting

| Problem | Likely cause / fix |
|---|---|
| "No OpenCode server is reachable" (external) | Start `opencode serve --port 4096` or switch to managed mode. |
| `opencode` binary not found | Install the CLI or set `opencodeBridge.opencodePath`. |
| Managed server did not become reachable | Check **OpenCode: Show Logs**. |
| Authentication required (401) | Set the password (external mode) or check `OPENCODE_SERVER_PASSWORD`. |
| "Still waiting for OpenCode…" | The model is slow or the provider is unreachable. Increase `responseTimeoutSeconds`, press Cancel, or check the Output channel. |
| No assistant reply streams | OpenCode needs a reachable provider (API keys configured in OpenCode). |
| Chat stays empty after reload | Check the Output channel; session history is restored from `/api/session/{id}/message`. |
| Answer stops with an "incomplete" badge | The provider or connection failed mid-answer. Read the banner (it names the model/provider), then use **Retry**, **Switch model**, or **Continue**. |
| Banner says the model is repeating itself | The provider is looping. **Stop** or **Stop and retry with a different model**; enable `autoStopRepetition` to stop automatically. |
| Very long answers stop formatting | Expected above ~200,000 characters. Use **Show full output** to read the rest; the stream itself keeps working. |
| Text looks garbled in a long reply | The provider sent a corrupted stream. The bridge forwards bytes exactly; retry, or switch models. |

## Development notes

- `src/chatController.ts` contains all chat behaviour and has no `vscode`
  import, so the send/prompt path is unit-tested with plain Node. It posts
  deltas only, deduplicates status messages, runs the repetition guard on the
  tail, and classifies provider failures.
- `src/repetition.ts` is the pure tail-only loop detector (char run >200,
  short pattern ≥8 repeats and ≥160 covered characters). Only the last 400
  characters are inspected.
- `src/errors.ts` is the pure failure classifier (connection → auth → rate
  limit → model → extension → unknown, in that priority).
- `media/streamRender.cjs` is the pure incremental render state shared by the
  webview (`window.OcStream`) and the Node tests: stable-block splitting,
  open-tail tracking, the 200k cap, and the `requestAnimationFrame` scheduler.
  Because the tests load the same module the webview loads, the render path
  is exercised even though there is no DOM in CI.
- `src/chatView.ts` is a thin adapter: HTML shell, strict nonce CSP, message
  forwarding, link opening.
- `src/client.ts` uses raw `fetch` for the endpoints that differ from the
  bundled SDK version, including the SSE stream, and parses
  `type = payload.type ?? sse.event` with text in `data.delta`.
- `media/markdown.cjs` and `media/slash.cjs` are shared by the webview
  (`OcMarkdown`, `OcSlash`) and the Node unit tests.
- `test/fixtures/reasoning-tool-permission.json` is a recorded v2.3.0 event
  sequence (reasoning → tool → permission → final text) used by the reducer
  tests; `test/slash.test.mjs` covers palette filtering,
  `test/chatController.test.mjs` covers context math,
  `test/streaming.test.mjs` covers delta-only streaming, the 50,000-delta
  budget, repetition banners and the recorded `ECONNRESET` replay,
  `test/repetition.test.mjs` and `test/errors.test.mjs` cover the pure
  detectors, and `test/streamRender.test.mjs` covers incremental rendering and
  the 200k cap.
- `npm test` currently reports **81 passing tests**; `npm run lint` reports
  **0 problems**; `npm run compile` (tsc) is clean.
- `npm run compile` only type-checks; the runtime artifact is the esbuild
  bundle in `out/extension.cjs`.

## What this extension does NOT do

It does **not** implement any LLM provider, API key handling, or model
routing. All model inference happens inside the `opencode serve` process you
run locally.
